# V0.30 — Transaction Journal

## Objectif

V0.30 transforme l'historique de sécurité de PISTE Studio en journal d'édition réversible sans supprimer les checkpoints persistants introduits auparavant.

Le principe est : une opération éditoriale validée conserve son état avant, son état après, son origine et les entités concernées.

## V0.30.1 — Reversible Journal

- index historique schema v2 avec migration à la lecture des index schema v1 ;
- snapshots avant/après pour les nouvelles transactions ;
- Undo et Redo persistants ;
- anciens checkpoints toujours lisibles ;
- un ancien checkpoint acquiert un état Redo lors de son premier Undo lorsque l'état courant est disponible ;
- identifiants historiques monotones, y compris après création d'une nouvelle branche d'édition.

## V0.30.2 — Provenance

Trois acteurs explicites :

- user : geste ou validation humaine ;
- agent : application explicitement confirmée d'une proposition de l'Editorial Agent ;
- system : opération technique interne lorsqu'elle sera nécessaire.

Chaque transaction peut porter :

- actor ;
- operation ;
- transaction_id ;
- affected ;
- reason.

Les mutations Storyline du kernel, la normalisation audio, le ducking, les crossfades et Apply Proposal sont reliés au journal.

## V0.30.3 — Undo / Redo UX

- endpoint local Redo ;
- bouton Redo dans l'appbar ;
- Cmd/Ctrl+Z : Undo ;
- Cmd/Ctrl+Shift+Z : Redo ;
- Ctrl+Y : Redo ;
- fallback navigateur autonome doté lui aussi d'une pile Redo.

## V0.30.4 — Branch & Coalescing Safety

- toute nouvelle édition après Undo supprime la branche Redo devenue obsolète ;
- les IDs ne sont pas réutilisés après divergence ;
- coalescing explicite disponible pour regrouper plusieurs micro-opérations du même geste ;
- aucun coalescing implicite après création d'une branche d'édition ;
- en cas d'échec de l'index du journal après mutation, tentative de restauration de la timeline précédente.

## Compatibilité

- timeline schema v6 inchangé ;
- secondes publiques inchangées ;
- historique schema v1 migré en mémoire sans exiger de conversion préalable du projet ;
- Canon, MASTER, versions et Tesseract inchangés ;
- les checkpoints persistants restent le filet de sécurité, le Transaction Journal les enrichit.
